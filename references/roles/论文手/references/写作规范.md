# 论文写作规范

## 一、读者模型与语言纪律

### 1. 评委画像（最高原则）

写作前始终记住读者是谁：

- 评委是**数学建模专家，但大概率不是本题领域专家**（尤其 A 题机理题）；他和参赛队一样"现学现卖"，且每篇论文的阅读时间有限。
- 因此论文不是"专业人士写给专业人士"的技术报告，而是"向懂数模的外行讲清你做了什么、为什么这样做、得到了什么"。任何一段文字评委读两遍还看不懂，就是写作的失败。
- "专业人士型友好"的文体（未解释的领域术语密集、每个数字捆绑多维讨论、高度名词化）在 AI 时代几乎必然被判为 AI 生成——这是比"写得浅"更危险的信号。

### 2. 语言三铁律

1. **平实质朴**：不滥用或卖弄专业术语，不故作高深地跨行援引"黑话"。
2. **严密专业**：去 AI 味 ≠ 大白话化。不打乱学术逻辑语序，不把专业词汇替换成生僻词；该用术语处精准使用（如 LSTM、NSGA-II 必须保留）。
3. **自然流畅**：像人写的——段与段之间有关联，每段有一个中心（说明、分析、解释或解决一个问题）。

人称：允许使用"我们"（"我们建立……""我们得到……"是国赛优秀论文的常态）；禁止口语化自称与网络腔。

### 3. 术语随用随解释

- 领域术语（如 Biot 数、Robin 边界、截断效率）首次出现时必须用一句话给出物理含义或直观解释；符号在 `术语表格.md` 统一定义后，仍需在首次使用处自然带出。
- 方法/算法名（如 NSGA-II、Hampel 跳变识别）首次出现时说明"它是什么、为什么选它"。
- 通用数学术语与竞赛公共知识（线性回归、灵敏度分析等）不必解释。

### 4. 密度纪律（双向）

- **下限**：每问必须有公式、有图表、有结果解读；关键算法必须有伪代码、步骤分解或流程图——不允许"纯文字解说像文科报告"。
- **上限**：不给每个数字捆绑多维讨论。每问只挑 1~3 个关键数值结果做"数值 + 物理含义 + 对比"的完整讨论，其余数值直接进表格；一个段落超过 6 个数字时收进表格。
- 数值给出后必须有解读："只报数字不解读"与"数字堆砌"同为反模式。

### 5. 机器视角清零（交付前硬性扫描）

以下文字是"生成过程废料"混进了成果，一律不得出现在论文中：

- **表格播报腔**："该表包含 4 条预览记录，字段包括……"——描述图表时直接提炼机理与结论，禁止罗列字段和表头。
- **元指令泄露**："正文需要回扣题目要求的……"等写作指令残留。
- **占位符残留**：`[待补充]`、"xxx"、"标准化计算公式书写为"（后面却没有公式）。
- **工作日志式标题**："6.2 缺失值进行时间相邻插补"——标题写研究对象与结论，不写操作步骤；标题一律短语化（"5.1 热传导方程的建立"，而非"5.1 问题一：炉温曲线机理模型的建立、辨识与正向仿真"）。
- **机器自述**："作为 AI……""根据输入数据……"。

### 6. 去 AI 味：文病三反 + 深度痕迹清单

**文病三反（基础层）**：

- **宏大动词平实化**："精准甄别/强势插入/彻底颠覆"→ 改为可核验的动作描述。
- **斩套娃长定语**：超过 40 字无停顿的句子拆成 2~3 句，长短结合、因果明确。
- **破机械排比**："首先…接着…然后…最后"是国赛摘要的标准过程链，可以使用；要破的是无信息增量的机械对称与空话排比，可错落为"一是/二是"或自然衔接。

**深度 AI 痕迹（交付前逐项扫描，均为"范式"而非词汇黑名单）**：

1. **同义词轮换**：AI 因重复惩罚在同一篇里对同一对象换用多个说法（"烟幕云团/烟幕弹/云团/干扰云"混用）；人类作者全文术语统一。同一概念全文只用一个名称，与 `术语表格.md` 对齐。
2. **系词回避**：该用"是"就用"是"（"这是一种线性模型"），不必每句都绕成"可被视为/呈现出……特征"。
3. **悬浮式"从而/进而"**：句末连挂两个以上"从而……进而……"制造虚假深度；每个"从而/进而"必须落实具体的因果对象。
4. **成对转折收束**："不是 X 而是 Y""但至少 Y"在一篇里反复出现是模板腔；全文至多零星使用。
5. **虚假范围**："从宏观到微观""从理论到实践"式空泛跨度，无实际内容支撑时删除。
6. **公式化挑战段**："尽管取得了一定成果，但仍存在局限性"模板句——局限必须写具体的（哪个假设、什么工况、导致什么偏差）。
7. **重要性膨胀 / 模糊归因 / 空洞结论**：见第一节第 7 条一致性纪律。
8. **破折号与冒号**：破折号每段 ≤1 个；冒号不禁止（"关键词：""综上所述……模型："都是刚需），只禁止用冒号串联 3 项以上的长列举（长列举改分条）。
9. **句长突变缺失**：全文句子长度过于均匀是机写强信号；长短句自然交错。

**受保护片段（改写/去 AI 味时禁改的五类）**：引用编号与参考文献条目；图表编号、公式及其编号；数据、百分比、度量关系；专业术语、定理、定义；直接引语与合规被动句（方法描述中的被动语态是学术规范，不是 AI 痕迹）。

**反编造铁律（改写场景的最高优先级）**：绝不为"降重/去 AI 味"补进原文没有的事实、数据、来源或文献；宁可保留一点生硬，也不编造。

**改写落点三级对照**：每次改写只有三种落点——降重不足（仍像 AI：模板句式原样保留）/ 降重过度（口语化：把"表明"换成"说白了"）/ 恰当（书面学术：判断落回具体数据、具体机制、具体条件）。目标永远是第三档："更像人 ≠ 更口语"。

### 7. 一致性

- 术语和符号严格服从 `术语表格.md`。
- 每段围绕一个明确论点，先给事实或推理，再解释其含义。
- 数值、单位、公式、图号、表号和引用前后一致。
- 不使用"专家认为""效果显著"等无来源表述；不用宣传性语言代替证据；创新点必须对应具体方法、实现和验证。
- 不虚构数据、实验、文献、赛题阈值或官方要求；禁止脑补赛题没有的阈值与要求。
- 两个模型得到相近结论时，如有比较价值，可如实保留并解释。
- 中文或英文表达服从目标竞赛和用户要求。

### 8. 数学字块排版纪律（与格式规范"凡数学皆公式"配套）

- 写作时把每个数学字块标记为公式，而不是打字符：凡含等号、**不等号**、上下标、希腊字母、运算符链、函数名、**坐标元组**、区间的字块（如 `RMSE=1.85 ℃`、`v_max=83.51 cm/min`、`(0, 200, 0)`、`[8.015, 9.415] s`、`y=0`、`y>0`），一律走行内公式接口（`body_rich`/混排 segments 的 `("math", latex)`）。
- **禁止**用 Unicode 上下标（²、⁻⁶、₁）、下划线（`v_max`）、尖角符（`x_i^e`）、程序式科学计数法（`1.26e-02`）冒充公式——这类写法是"机器味"最直接的来源。
- 白名单（仅此三类可留文本，详见 `论文格式规范.md`"凡数学皆公式"节）：数字+单位且无数学结构（20%、60~120 s）；纯英文字符串（FY1、result1.xlsx）；字母+非下标数字编号。
- **禁逗号堆积**：三条件及以上约束写成 cases 大花括号竖排，连等计算用 aligned 等号对齐（一行一句）；4 项及以上并列数据/映射/分配关系改用三线表、示意图或换行对齐呈现（判断标准与接口见 `论文格式规范.md`"多数据呈现纪律"）。
- 图题/表题不堆参数与单位：工况条件（"v=70 cm/min，175/195 ℃"等）写进正文句子，题注只写"图 X 最优解炉温曲线"式干净短句；表头单位写成 `cm/min` 式正体文本或并入公式，不用 Unicode 负指数。
- **图表编号铁律**：全文按出现先后连续编号（图1、图2…/表1、表2…），图表分编，绝对禁止章节连字符编号（图5-1、表3-2）；写作时引用编号与题注一致。

## 二、评阅人抓分方法论

数学建模竞赛评阅遵循"假设的合理性、建模的创造性、结果的正确性、表述的清晰性"四项基本原则。通用分项权重约为——模型假设合理性约 20% / 建模创造性约 25% / 结果表述清晰性约 25% / 论文格式规范性约 15% / 参考文献约 15%。**摘要与结果表述合计权重最高（约 50%+）**；评阅人常先花几十秒筛摘要与关键图表，再决定是否细读，抓分必须从摘要和结果入手。以下方法覆盖 CUMCM / MCM-ICM / APMCM 等各类竞赛，具体篇幅与结构始终以当届官方规则为准。

### 1. 摘要：国赛叙事链（CUMCM）/ 四段式（MCM/ICM）

**CUMCM 摘要 = 带数字的叙述**。篇幅基准（2020—2025 国一实测）：750~1000 汉字、3~6 段，独立第一页，不放公式图表（行内小符号可用）。

**结构链：**

1. **总述段**（强烈推荐）：两种开法二选一——
   - 背景式：背景 1~2 句 + 本文总方法一句话 + 价值一句；
   - 公共基础式（2025 国赛实测）：开头段直接交代全文共用的模型元件（如"首先给出了各物体的位置函数，引入布尔函数判断遮挡是否有效"），随后逐问段直接引用，比背景套话信息密度更高。
2. **任务单元段**：默认逐问各一段（"针对问题X，……"），但组织可软化——后问是前问扩展时用"在问题X模型的基础上加入……"体现递进；共享模型且结果关联的分问可合并；按场景/阶段/模型链组织亦可，只要任务映射清楚。
3. 每段内部走**方法—答案闭环五要素链**：`任务/瓶颈 → 决定性处理 → 核心模型 → 关键结果 → 结论/验证`。"核心方法"与"得到什么"不可同时缺失；**结果紧跟产生它的方法**，禁止前半部堆模型、末尾堆结果。
4. **可选收束句**：模型检验 / 灵敏度 / 评价一句——只在确实增加可信度时保留，正文没有就不补；没有新的总体结论就在最后一问自然结束，删"具有重要意义/可广泛推广"。
5. **关键词**："关键词："加粗，3~5 个词（空格或分号分隔），至少含 2 个具体方法 + 2 个题目领域词，避免"数学建模""优化"等空泛词。

**数字纪律（评委判断门）**：每个数字入摘要前问一句"能否帮评委快速判断得出了什么、效果如何"；每问 1~3 个关键数值，必须带对象/指标/条件/单位；**保留正文原精度，不擅自四舍五入或统一小数位**；口径冲突时宁可省略也不自选更优值。

**信息分级（写作时的取舍尺）**：S 级=核心答案/核心模型/最终方案/关键量化结果（必留）；A 级=改进/关键处理/创新/关键检验（优先留）；B 级=理解主链必需的过程（择优留）；C 级=原理复述/背景铺陈/软件名/附件导览（删）。篇幅分配顺序：核心方法 > 关键结果 > 主要结论 > 创新改进 > 必要处理；按问题价值分配篇幅，基准建模问可短写，核心决策问多写。

**自检（信息损失六类，写完逐条排除）**：有模型没结果 / 有结果没数值 / 有创新没体现 / 有检验没说明 / 方法过多结果过少 / 各问篇幅失衡。

**三条实证规则（2025 国赛最新实测）**：

- 摘要内一般省略"详见表X/附件"指引与图表编号；**唯一例外：赛题显式指定的输出文件**（如 2025A 题要求结果存入 result1/2/3.xlsx）必须在摘要相应问末尾点名（"……，其余数据见附件 result1.xlsx"），这是交付凭证。
- **交叉验证与负结果可以进摘要且加分**："用粒子群算法重新求解验证，两算法相对误差仅 0.01%"；"决策变量维度过大不能直接求解，故分层次优化"——失败转化叙事是可信度的强信号。
- 创新不写"本文创新点"单列段，而是证据链嵌在叙述里："瓶颈 → 实际实施的设计 → 对结果/效率/可靠性的可核验作用"。

Word 排版时摘要加粗纪律：关键方法名与关键结果数字加粗（2025 国一实测共性），**短语级**（核心模型/关键改进/核心指标/重要结果），同一信息仅首次加粗，不整句整段加粗；LaTeX 排版可省略加粗。

**题型主干（每段组织语言的默认主线，按赛题类型取用）：**

| 题型 | 摘要主线 |
|---|---|
| 机理类 | 关键物理假设 → 状态方程/反演 → 数值求解/参数估计 → 关键状态值 → 误差与适用条件 |
| 优化类 | 决策变量与目标 → 约束刻画 → 求解算法（为何选它）→ 最优值与方案 → 检验/对比 |
| 预测类 | 数据特征 → 模型选择与理由 → 训练/拟合 → 预测值 → 精度指标与检验 |
| 评价类 | 指标体系 → 赋权方法 → 综合评价值/排序 → 稳健性 |
| 分类/判别类 | 特征构造 → 分类器与阈值 → 准确率/混淆矩阵 → 误判分析 |
| 统计类 | 数据与检验假设 → 统计量/检验方法 → 显著性结论 → 效应量 |
| 运筹/调度类 | 资源与任务建模 → 约束与目标 → 求解策略 → 调度方案与利用率 |

**MCM/ICM 摘要**沿用严格四段式：**问题与挑战 → 方法 → 关键结果 → 验证与创新**，关键结果必须带具体数值（如"得到最优配比 (0.42, 0.31, 0.27)，误差 1.8%，优于基线 23%"）。

**两赛通用**：摘要最后写，基于已定稿正文；摘要与正文必须完全一致（摘要说用 LSTM、正文却是 BP，会被质疑诚信）；杜绝"效果良好/得到了较好的结果"等空泛表述。

### 2. 结论段"一图一数一句"

每个结论紧跟：一张图 + 一个具体数值 + 一句话解释。例："得到 X=12.3，意味着每天最多调度 12 辆车，与现实 10-15 辆一致。"避免只报数字不解读。解读用"现象 + 这是由于……（机理）"句式——只写现象不给机理是优秀论文都避免的。

### 3. 评阅人快速抓分路径

评阅人按 摘要 → 问题重述 → 模型建立 → 结果图 → 结论 抓分，每个部分都有独立得分点：

| 部分 | 抓分点 |
|---|---|
| 摘要 | 问题、方法、关键数值、验证、创新一句话讲清 |
| 问题重述 | 用自己的语言重述，明确核心任务、输入、约束和输出 |
| 模型建立 | 每个子问题结论有对应公式、参数、输入输出、验证方式 |
| 结果图 | 每子问题至少 1 流程图 + 1 结果图，图表编号、标题、正文引用齐全 |
| 结论 | 直接回答题目要求，关键数值突出 |

### 4. 反模式对照自查

写作时对照以下高频扣分反模式自查：

**摘要类（扣分最重）**
- 摘要无定量结果、结构混乱、与正文不符、关键词空泛、篇幅失控、塞公式图表。
- 数字堆砌无叙述（"数字本身"而非"带数字的叙述"）；术语无解释堆叠。

**结果分析类**
- 只报数字不解读；纯表格无图；图表配色丑；图表无编号标题；灵敏度只改代入值不重新求解；灵敏度参数乱选。
- 每个数字捆绑三维以上讨论导致密度泛滥；一段超过 6 个数字未收进表格；表格播报腔（罗列字段表头代替机理结论）。

**模型选型类**
- 直接套课本模型无针对性处理；模型与问题不匹配；候选模型同族假对比；选型理由薄弱；选 NP-hard 不验证可行性。

**假设符号类**
- 假设无支撑、假设过多/过少；符号重复定义、无单位、未定义先出现；量纲不一致。
- 假设带"依据/必要性/影响范围"式长篇自我辩护（每条至多半句必要性说明）。

**结构类**
- "先全部建模、再全部求解"两段式，模型与问题割裂。
- 问题分析搬运"总体思路/数据特征/关键难点"等中间产物，或写入求解后才知道的后见之明。
- 独立敏感性大章（超过 2 页）；独立结论章复述摘要。
- 附录只有代码清单表、没有真实代码。

**机器视角类**
- 表格播报腔、元指令泄露、占位符残留、工作日志式标题、机器自述（见第一节第 5 条）。

**语言病类**
- 宏大动词（"精准甄别、强势插入、彻底"）、套娃长定语（一句 40+ 字无停顿）、机械排比、空话拔高（"具备稳定落地的工程应用价值"）、名词化翻译腔。

### 5. 创新性信号

"建模创造性"权重约 25%，是冲奖关键。创新必须对应具体方法、实现和验证，并按以下信号呈现：

- **自创算法**：针对赛题特殊结构设计的算法，说明算法动机。
- **跨领域模型融合**：把 A 领域方法用于 B 领域，论证合理性而非简单堆砌。
- **经典方法针对性改进**：明确改在哪里、为何要改，附改进前后对比验证。
- **新颖数学抽象**：对问题的数学抽象简化得当且保留本质。
- **多方法协同**：不同子问题用不同方法并论证衔接逻辑。

任何创新都必须伴随**对比验证**（改进前后对比、不同方法对比、灵敏度分析），证明有效而非自说自话。

## 三、国赛专项规则（CUMCM）

以下规则来自对近年国赛 A 题国一论文（2020/2022/2023/2024 共十余篇）的精读归纳，是"大部分优秀论文都这样做"的共性；当届官方规则与之冲突时以官方为准。

### 1. 骨架与篇幅锚点（国一论文实测）

| 章节 | 篇幅锚点 | 组织要点 |
|---|---|---|
| 摘要 | 750~1000 汉字、3~6 段，独立第一页 | 总述段 + 逐问叙事链（可递进/合并）+ 关键词 3~5 个 |
| 一、问题重述 | 约 700~800 字 | 1.1 背景（可带引用、可配 1 张实景/示意小图）→ 1.2 问题提出 → 逐问复述 |
| 二、问题分析 | 约 600~900 字 | 每问一段 150~250 字前瞻式；或"2.1 问题一的分析"小节式，两式并存 |
| 三、模型假设 | 4~8 条 | 每条一句话，至多半句必要性说明 |
| 四、符号说明 | 半页~一页 | 三列三线表（符号/说明/单位），无单位填"/" |
| 五、模型的建立与求解 | 每问 3~8 页 | **按问题联动**，见下条 |
| 六、模型评价 | 1~2 页 | 检验与灵敏度 + 优缺点（优点 2~4 条带证据 / 缺点 1~3 条具体 / 推广 1~2 条） |
| 参考文献 | 5~10 条按需（2025 起含 AI 工具条目） | GB/T 7714，双向对应 |
| 附录 | 不限 | 索引清单 + 答案全表 + 核心代码 |

正文总篇幅典型 9,000~15,000 字词单位、正文约 20~30 页（近年国一实测约 9,000~16,000 字、正文 19~33 页）；以此为完整度质量目标，**禁止为凑字数填充**。

### 2. 按问题联动（硬性）

- 主体章按问题组织：每问一节（问多时每问一章，章名可为"问题X的模型的建立和求解"），内含"模型建立 → 模型求解 → 结果与分析"。
- 禁止"先全部建模、再全部求解"两段式；多问共用的公共底座（坐标系、通用控制方程）可前置，但不超过 1.5 页。
- 问题分析章按问题逐问**前瞻式**书写：本质判断 → 难点 → 拟用模型/算法/关键步骤。方法选择必须给理由，用"先破后立"句式（"由于决策变量很多，传统遍历方法行不通，因此采用遗传算法"）。递进关系写明"在问题X模型基础上添加……约束/改进……"。
- 问题分析两种体式并存（任选其一，全文统一）：段落式（"对于问题一，……"每问一段）与小节式（"2.1 问题一的分析"每问一小节）均为国赛实测共性；章首可配一张"各问题关系图/技术路线图"轻量呈现整体逻辑。
- 问题分析禁止搬运依赖关系 DAG、数据报告等中间产物原文；禁止写入求解后才知道的后见之明。

### 3. 模型建立与求解的每问内部范式

- **模型建立**：动机一句 → 示意图 → "设/令/记……为 x"引入符号 → 逐步推导（"由……可得："）→ 模型总成。优化类问题在约束分析时**逐条命名约束**（"任务分配约束：……""投弹间隔约束：……"，约束名加粗），每条约束紧跟公式与一句说明。
- **模型汇总**：每问模型建立末尾设"模型汇总"小段（2025 国赛实测），用"综上，问题X的……模型可表述为："把目标函数 + 全部约束合成一个 max/min + s.t. 块——让评委一眼看到该问模型的完整形态。
- **模型求解**：Step1/2/3 步骤分解、伪代码（带行号）或算法流程图 + 关键中间结果；数值求解的"先粗后精"要写清（如"先以 Δt=1s 遍历缩小至 [412s,413s]，再以 Δt=0.0001s 精细搜索"）；对采样精度/步长的灵敏度交代可放在求解小节开头。
- **结果与分析**：图不裸奔——图前一句引入（"计算了……，如下图 X 所示。"），图后解读（"图中 X 表示……，我们发现……，此外……"）；结论分条，每条"现象 + 这是由于……（机理）"；超大结果表正文放部分（"部分结果如表 X 所示，全部数据详见支撑材料（文件 X-工作表 N）"）；**赛题显式指定的输出文件**（如 result1.xlsx）在结果节点名交付。

### 4. 检验、灵敏度与评价

- 灵敏度/稳健性检验：嵌入该问题末节，或设不超过 2 页的独立小章；检验条目与被检验的假设一一对应。
- 模型评价：优点 2~4 条，每条一句且带证据；缺点与改进 1~3 条。**诚实的负面结果是加分项**（如"极端工况下 R² 探负（-0.9218）"写进局限，评委最爱）；拒绝"运行快、精度高"式低级废话。
- 国赛可不设独立结论章（结论融于摘要与各问末尾）；如设，仅数条编号要点，禁止复述摘要。

### 5. 附录三大件（硬性）

1. **附录索引页**："附录"居中 + 清单，含支撑材料文件列表（文件名 + 功能注释两列）。2025 国赛实测：清单中《AI工具使用详情》列为支撑材料第一项已成标配（见本节第 6 条）。
2. **答案完整大表**：全精度（8~9 位小数）——正文结果表只给 4~6 位，**正文截位、附录全精度**。
3. **核心代码**：按问题分文件原样贴出，语法着色、中文注释密集（参数逐行注单位），**带行号**（2025 国赛实测）；删去库引用、数据读取等非核心噪音，不加解释说明。可按"附录A 文件列表 / 附录B 代码"分节。

### 6. AI 使用合规（按当届官方规则执行）

CUMCM 自 2025 年起要求披露 AI 使用情况。当届规则要求时，交付三件事：

1. **正文标注**：AI 生成内容处在正文相应位置加角标（用 Word 引用功能实现可跳转）。
2. **参考文献列出所用 AI 工具**（与文献共享编号序列）：`[编号] 工具名称，版本/型号，开发机构/公司，使用日期`。2025 国赛实测样例：`[3] Kimi, K1.5, Moonshot AI, 2025-09-06.`、`[4] DeepSeek, DeepSeek-V3.1, 深度求索（DeepSeek）, 2025-09-07.`
3. **支撑材料含《AI工具使用详情》**：工具版本、使用目的环节、关键交互记录、采纳与人工修改情况。

策略建议：主动声明 AI 嫌疑最大的环节（语言润色、伪代码排版、公式排版、三线表整理等约 4 处），其余如实从简；具体范围以当届官方规则和用户要求为准。

### 7. 高频句式库

- 引入符号："设……为 x""令……""记……为……"
- 推导衔接："由……可得：""代入式(1)，得：""联立式(1)(2)，采用……可解得……"
- 图件衔接："如图 X 所示，……""……，如下图 X 所示。""图中 X 表示……，我们发现……，此外……"
- 模型收束："综上所述，我们建立……模型：""联立以上各式，得到……的优化模型：""综上，问题 X 的……模型可表述为：max/min …… s.t. ……"
- 方法论证："由于……，传统……方法行不通，因此采用……"
- 递进衔接："在问题 X 模型的基础上，补充/加入/修正……""与前一问不同，本问的关键在于……"
- 结果指引："部分结果如表 X 所示，全部数据详见支撑材料（文件 X-工作表 N）""最优策略为……，结果详见 resultN.xlsx（赛题指定输出文件）"
- 结论分条："现象句。这是由于……（机理）。"
